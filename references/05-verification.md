# 3.5 验证回归（工件冻结）

## 目标

在干净上下文中、由非实现者判定候选版本是否合格。实现者自检是快速失败闸，不是验证——同一上下文里既当运动员又当裁判，测出的是记忆而不是能力。

## 输入

- 候选 commit 的提取副本（见"隔离工作区"）
- `iterations/{任务编号}/02-验收标准.md`
- eval 集（`evals/`）与基线（`results/`）

**不给验证方**：02-变更方案、实现期对话、调试结论、偏离记录——验证者被实现意图带偏后，测的就不再是工件本身。

## 验证者与上下文

验证必须满足两个条件：

1. **非实现者**：没参与本次修改的 agent / 子任务 / 新会话
2. **干净上下文**：不包含正确答案、临时路径、调试结论和人工裁决等开发期信息

机制二选一，**spawn 优先**：

- spawn 隔离子任务，只给**工件 + 02-验收标准**，不给变更方案、不给实现期对话
- spawn 不可用或被沙箱拒绝时，**立即切换**为生成验证交接指令（含工件位置、验收标准位置、报告落盘路径），由用户开新会话执行

不要因为 spawn 失败就手工搭建隔离目录树补救——隔离要满足的是"验证者不接触实现者的上下文"，不是物理隔离的文件系统，为此消耗大量时间是满足一个不存在的条件。

只提供正式运行时真实可获得的输入；不提供参考答案或开发阶段讨论；不共享前一次运行的临时记忆和补丁。

## 隔离工作区

验证不得影响工件仓库的 git 记录：

- 验证对象是候选 commit 的**提取副本**：`git archive {hash}` 解包到工件仓库的临时目录，确保可以让用户用完即删。不用 `git worktree`（元数据写进原仓库 `.git/`）、不切原仓库 HEAD、不在仓库内建任何验证用目录
- 验证写回工件仓库的产物**只有 05 报告一份**——它是流程留痕的一部分，必须落进 `iterations/{任务编号}/`
- 提取的源码树、验证交接指令文件、验证过程的所有中间输出，全部留在临时目录，**删除时机由用户决定**——中间文件可能需要人工查看（排查验证结论、复核失败原因），验证 agent 不自行清理，只在 05 报告中注明临时目录位置

## 回归范围

按分级（P1/P2/P3）和 02 的影响面结论，查分层回归表定最低范围：

| 修改范围 | 最低回归范围 |
|---|---|
| 文档或局部提示调整 | 当前失败测试、核心功能测试 |
| 单个工件脚本 | 当前失败、核心测试、结构不变量、端到端流程 |
| schema 或输入输出接口 | 上游契约、下游契约、端到端流程 |
| 共享脚本或组件 | 全部已知调用方、端到端流程、验证集 |
| 触发 description | Triggering 正例、改写正例、负例和相邻工件 |
| 发布门禁或校验器 | 正确样本通过、错误样本阻断、调度层停止交付 |

## 执行三类测试

- **Triggering tests**（工件是否在正确时间加载）：明确请求、口语化改写和隐含请求能触发；无关请求不触发；相邻工件不互相抢占。只有 description 或触发边界变化时才需重点扩大。
- **Functional tests**（实际任务能力）：正常、缺失、异常和边界输入；用户必须参与裁决的情况；工具失败、重试和中断路径；文件结构、schema 和业务规则。
- **Performance comparison**（新版本是否值得发布）：任务成功率和断言通过率；用户纠正和人工介入次数；工具失败和重试次数；token 消耗和运行时长。显著性阈值由业务方约定。

## 按顺序运行

当前失败测试 → 当前工件核心测试集 → 受影响调用方测试 → 端到端流程测试 → 独立验证集。

**验证期间候选版本不得再修改**——边测边改，对比的就是移动靶，基线比较在方法学上直接失效。需要改即走回跳边解冻重做。

## 人工裁决

程序和 agent 判不了的标准（业务口径、正式名称等）：把实际输出提交给用户看，人的结论记入验证报告的「人工裁决记录」。新版本输出按既有约定落 baseline 库 `results/{eval_id}/{候选版本}/`。

## 产物与轨迹双检查

最终产物说明"发生了什么"，执行轨迹说明"为什么发生"。检查：是否读取了错误材料；是否跳过关键校验；是否先产生错误结果再用运行时补丁掩盖；是否修改最终产物而没有修复工件；是否依赖开发对话中的答案。轨迹留在平台，需要时向用户索取。

## 验证报告

每个候选版本一份：`iterations/{任务编号}/05-验证报告-{候选commit短hash}.md`，由验证 agent 在验证结束后一次写成（模板：`assets/templates/05-验证报告模板.md`）。内容：回归范围与执行记录、逐项结果（标准编号 × 层 × 结果 × 指针）、人工裁决记录、出口结论。

## 出口（三类）

- **前进**：门禁全部通过 → 3.6 发布
- **回跳**：回归失败且 `retry < N` → 3.4 修改实现（工件解冻），报告写明哪条 eval 挂了、失败摘要；根因误判 → 3.1 问题归因
- **阻断**：关键断言失败且不可修复 → 终止

回跳重试上限建议 N=3，超限升级人工——这是"不断追加案例词条"反模式的机械化防呆。
