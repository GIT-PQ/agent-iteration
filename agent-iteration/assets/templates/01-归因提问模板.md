# 归因提问模板 v1

> **使用方式**：将代码块内的【提问 prompt】整段复制到执行平台对话，替换 `{{失败现象}}` 槽位。说明段不粘贴。平台 Agent 按内嵌回答模板作答，回答原样 copy 回 `iterations/{任务编号}/01-归因问答.md`。
>
> **业务无关性**：本模板只承载提问框架和回答结构，业务上下文全部通过槽位注入，不在模板内硬编码。

## 提问 prompt（整段复制，替换槽位）

````text
你是刚刚执行完本次任务的原始 Agent。我正在对本次任务结果与预期的偏差做问题归因，
请依据你的执行轨迹（不是猜测）回答以下问题。

【失败现象/用户反馈】

{{在此粘贴：用户反馈原文、失败产物描述、或预期与实际的差异}}

请回答：

1. 执行回顾：按时间顺序列出本次执行的关键步骤——读了什么材料、
   调用了什么工具、每步的产出和判断依据。
2. 偏离点：输出从哪一步开始偏离预期？你当时为什么那样处理？
3. 责任归类（可多选，每项给理由）：
   - 工件设计问题：指令缺失、职责冲突、步骤顺序不合理
   - 脚本实现问题：结构被破坏、重复输出、校验失效
   - Agent 执行问题：跳过步骤、误读报告、临时修补产物
   - 输入材料问题：材料缺失、矛盾、OCR 污染、事实无法确定
   - 人工裁决缺失：多个候选都合理但无法自动确定
4. 根本原因与直接诱因：根本原因 = 为什么进入错误状态；
   直接诱因 = 为什么本次表现为当前错误。两者可能不同，分别陈述。
5. 不确定项：哪些你无法确定、需要人工裁决？

约束：
- 引用轨迹原文作证据，标注出处步骤；
- 严格区分"事实"与"我的推断"；
- 不知道就写不知道，不要补全。

请按以下结构作答（标题保留，括号内占位说明删除）：

```markdown
### 执行回顾
（步骤列表）

### 偏离点与当时判断

### 责任归类
（类别 + 理由 + 证据）

### 根本原因 / 直接诱因

### 不确定项
```
````
