# 验证报告模板 v1

> **使用方式**：验证回归阶段（3.5）每个候选版本一份——`iterations/{任务编号}/05-验证报告-{候选commit短hash}.md`，由验证 agent 在验证结束后一次写成。
>
> **定位**：留痕证据，不是工作界面。对话承载过程（agent 在对话中报告结论、向人提交裁决项），本文件承载结论的存档。新版本输出落在 `results/{eval_id}/{候选版本}/`，本文件只记结论和指针。
>
> **人工层**：程序和 agent 判不了的标准（业务口径、正式名称等），在对话中提交给人看实际输出，人的结论由 agent 记入「人工裁决记录」。

## 落盘骨架（复制为 iterations/{任务编号}/05-验证报告-{hash}.md 后填写）

```markdown
---
任务编号：T-001
日期：YYYY-MM-DD
验证者：（须为非实现者，见 4.2）
候选版本：commit 短 hash
依据：02-验收标准.md、03-测试准备.md、04-变更记录.md
---

## 回归范围与执行记录

- 回归范围：（按分层回归表选行，引 02 的影响面结论）
- 执行顺序：当前失败 → 核心 → 调用方 → 端到端 → 验证集

## 逐项结果

（层：程序 = 脚本断言 / agent = grader rubric / 人工 = 见人工裁决记录；
指针指向 eval id 或输出路径）

| 标准编号 | 层 | 结果 | 指针 |
|---|---|---|---|

| S2 | agent | 通过/失败 | rubric 结论 |
| S3 | 人工 | 通过/失败 | 见人工裁决记录 |

## 人工裁决记录

（对话中提交给人的项：判定要点、指向的实际输出、人的结论及理由）

| 标准编号 | 判定要点 | 查看对象 | 人工结论 |
|---|---|---|---|
| S3 |  | results/{eval_id}/{hash}/output | 通过/不通过 + 理由 |
```
