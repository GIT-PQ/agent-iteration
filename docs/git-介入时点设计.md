# agent-iteration skill — git 介入时点设计

> 2026-09-14。基于《Agent迭代指南》v2 推导的 git 介入时间轴，作为《git-使用缺陷清单.md》的修复依据。
> 前提：指南 4.6 只规定了 git 的两个写入时点（3.4 出口 commit、3.6 门禁后 tag），但指南自身的核心机制——触及清单 = diff 边界、基线能力、验证对象 = 提交对象——隐含要求更早、更多的介入点。

## 总原则

**git 的每一次写入对齐一个状态机出口，每一次只读对齐一个证据需求；全程 append-only，任何时点不 reset、不 rebase、不移动已打出的 tag。**

## 介入时间轴

| 时点 | git 操作 | 支撑指南的哪条机制 |
|---|---|---|
| **入流程时（3.1 前）** | 未 git 化则 init + 初始 commit；**确认工作区干净**（脏则先提交为"任务前状态"或如实记入 01）；**钉住起点 hash** | "触及清单 = diff 边界"（3.2）需要干净的 diff 基准；"分析基于当前已发布版本"（反模式表）需要把"当前版本"钉成不可变指针，否则归因对象是移动靶 |
| **3.1–3.3（只读期）** | git 只读：`log`/`diff` 做归因分析；旧版本运行基于起点 hash 的提取副本，而不是工作区现状 | 3.3 基线的"修改前工件版本"应钉为**起点 commit hash**，而不是指南里含糊的"Git 提交或快照"——跨版本对比要求旧版本身份不可变 |
| **3.4 出口（唯一工件写入点）** | 候选 commit——**只含触及清单内的工件改动** | 指南 4.6 已有："hash 才不可变，验证对象 = 提交对象，零缝隙" |
| **候选 commit 之后、验证之前** | **留痕 commit**：iterations/ 01–04、evals/、results/ 基线 | 指南最大的缺口，见下节"关键抉择" |
| **3.5（冻结期）** | 只读：`git archive {候选hash}` 提取验证副本；验证结束后 05 报告写回 + 一次留痕 commit | "干净上下文"的物理载体就是 archive；05 是流程留痕，落盘不 commit 则 3.6 永远建立在脏工作区上 |
| **3.6 发布** | annotated tag 指向候选 commit；changelog 作为 tag 之后的发布留痕 commit | 指南已有，但需**显式接受 HEAD 永远超前于最新 tag** 这个事实——发布留痕（changelog、05、日志）生活在 tag 之后，这是设计而非事故 |
| **回滚** | checkout/交付旧 tag + 追加回滚条目 commit，**不重写历史** | "回滚点 = 上一版本 tag"成立的前提是历史 append-only；reset --hard 会连带抹掉发布留痕 |

## 关键抉择：留痕 commit 必须在候选 commit 之后

这是缺陷清单中缺陷 1 和缺陷 2 的共同根源，也是修复的枢纽。

注意指南 2.3 的原设计：**迭代日志在 vault 里、随 vault 自己的 git 版本化**——和工件仓库是两个仓库。skill 把它并进工件仓库时，没有补上对应的规则，于是产生两难：

- 日志放在候选 commit 之前或随候选一起提交 → 02-变更方案进入候选 commit 的祖先 → `git archive {候选}` 的验证副本里验证者能读到变更方案 → **读者边界失效**（缺陷 1）；
- 日志一直不提交 → tag 序列永远建立在脏工作区上，state_check 的"文件即进度"与 git 状态脱节（缺陷 2、3）。

而放在候选 commit **之后**，两个机制同时成立：

- 验证副本天然不含变更方案（读者边界成立）；
- 候选 commit 的 diff 相对父提交就是纯工件改动（diff 边界成立）；
- "文件即进度"继续走文件系统，git 只是在每个出口钉一次快照——两者职责分离，互不替代。

## 指南已写对 vs 缺失

**已写对**：commit 是检查点 / tag 是定稿；验证对象 = 提交对象；失败候选留在历史；回滚点 = 上一版本 tag。

**缺失**：

1. 入流程时点的介入（init / 干净检查 / 钉起点 hash）
2. 基线版本应钉为 commit hash（消除"Git 提交或快照"的含糊）
3. "留痕 commit"这个类别及其必须晚于候选 commit 的顺序约束
4. tag 永远超前于 HEAD 的显式声明（发布留痕生活在 tag 之后是设计而非事故）
5. 回滚的 append-only 语义——"切换 tag 指向回滚点"这句应改为"交付/检出回滚点 tag 并追加回滚条目 commit"，明确禁止 reset --hard 与移动已发布 tag
