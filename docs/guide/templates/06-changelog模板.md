# changelog 模板 v1

> **使用方式**：发布阶段（3.6）在工件仓库 `CHANGELOG.md` 顶部追加一条（不新建文件）。changelog 是累积文件，本模板是**条目骨架**，不是文件骨架。
>
> **生成时机**：发布时点一次生成——tag 打向验证过的候选 commit 后追加。失败候选不进 changelog（那里是定稿事实，不是意图）。
>
> **定位**：版本视角的唯一入口。维护者回答"这个版本改了什么、能不能用、出事滚到哪"全靠它；任务编号 ↔ 版本 ↔ 根因 ↔ 回滚点在此汇合。

## 条目骨架（追加到工件仓库 CHANGELOG.md 顶部）

```markdown
## v{major}.{minor} — YYYY-MM-DD

- 任务编号：T-001
- 修改层级：description / 流程 / 脚本 / schema / 共享组件 / 校验器
- 根因摘要：（引 01-归因问答的最终归因，一句话）
- 影响的调用方清单：（引 02-验收标准的影响面）
- 回滚点：v{上一版本}（tag）
- 验证报告：iterations/T-001/05-验证报告-{hash}.md

### 门禁八条对照

1. 当前失败已进入回归集并通过 ——（指向 05）
2. 原有关键断言没有退化 ——（指向 05）
3. 结构不变量全部通过 ——（指向 05）
4. 共享调用方没有出现新问题 ——（指向 05）
5. 验证集表现没有下降 ——（指向 05）
6. 执行轨迹无未解释补丁 ——（人工确认）
7. 人工反馈无未解决问题 ——（人工确认）
8. 上一版本可回滚 ——（tag 检查）
```

## P3 调整小节骨架（P3 不升版本号时，追加在当前版本条目内，不打新 tag）

```markdown
### YYYY-MM-DD P3 调整

- 任务编号：T-001
- 调整摘要：
- 验证报告：iterations/T-001/05-验证报告-{hash}.md
- 门禁：无行为影响确认 + 当前失败测试通过（P3 最小门禁，指向 05）
```

## 回滚条目骨架（回滚时追加，不删除被回滚版本的条目）

```markdown
## v{major}.{minor} 已回滚 — YYYY-MM-DD

- 回滚至：v{上一版本}
- 原因：
- 触发证据：（指针；详情由重入归因的新任务 01-归因问答承载）
- 后续任务：T-xxx
```
