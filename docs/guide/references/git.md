# 版本库与 git 使用规范

> 本文是《Agent迭代指南》§4.6 的展开，为版本库与 git 管理的权威规范。指南 3.4 与 3.6 只保留 git 的状态机语义（提交冻结、打 tag 定稿、回滚重入），操作边界、时机与命令一律以本文为准。全篇为工程化设计，非外部来源直接支持。

## 1. 管辖边界（管哪些）

### 1.1 存留原则

1. **迭代对象本身必存**：工件源码是 diff 边界与 tag 指向的对象，无可再生之源。
2. **可再生的不存**：能从仍被存储的源确定性重放的产物，不进版本库。

### 1.2 产物存留对照

| 存留档 | 内容 | 依据 |
|---|---|---|
| **进 git（唯一事实）** | 工件源码、`CHANGELOG.md`、`evals/`、`iterations/` 留痕（01-05 全套） | 不可再生，承载「为什么失败 / 改什么 / 改对没」 |
| **不入库（可再生的）** | `results/` 基线输出 | 可由「旧 tag + eval 输入」重放 |
| **不入库（敏感）** | `03-测试准备.md` 中的**脱敏对照表** | 敏感信息唯一还原路径；由人 commit 时裁决剥离 |

> `results/` 基线只在 3.3 生成、3.5 对比用，迭代闭合后可清——它的源是「旧 tag + eval」，不是新事实。

### 1.3 最小目录骨架

工件仓库以下 5 项必须存在，其余目录（docs/、data/ 等）按需再建：

```
工件仓库（最小骨架）
├── <工件源码>        必须（git 版本化）
├── iterations/       必须（留痕，入库）
├── evals/            必须（脱敏回归断言，入库）
├── results/          必须（目录在；内容不入库，.gitkeep 维持）
└── CHANGELOG.md      必须（版本视角索引，入库）
```

### 1.4 .gitignore

```gitignore
# 基线输出：可再生成，不入库；目录以 .gitkeep 维持骨架
results/*
!results/.gitkeep
```

> 脱敏对照表若随 `03-测试准备.md` 落盘，无法用 gitignore 机械剥离，靠人在 commit 时裁决（见 1.2）。

## 2. 操作分工（谁动）

git 操作按「写 / 读」分治：**写 = 不可逆或难逆动作，人执行、skill 提醒时机；读 = 无副作用，skill 自动**。

| git 操作 | 类别 | 执行者 | skill 行为 |
|---|---|---|---|
| `init`（仓库未 git 化） | 写 | 人 | 启动时提醒 |
| `commit`（候选） | 写 | 人 | 3.4 出口提醒，带冻结语义 |
| `commit`（留痕 + changelog） | 写 | 人 | 3.6 归档提醒 |
| `tag` | 写 | 人 | 3.6 门禁后提醒 |
| `rollback` | 写 | 人 | 生产恶化提醒（切回上一 tag） |
| `archive` | 读 | skill 自动 | 3.5 验证隔离取冻结副本 |
| `diff` | 读 | skill 自动 | 越界自查（触及清单） |
| `log` | 读 | skill 自动 | 取上一 tag 作回滚点 |

> 提醒不是「该提交了」这么笼统——它必须携带**冻结语义**：3.4 出口的 commit 是 3.4→3.5 的守卫，人执行后才放行进入验证，否则「验证期间候选不得改动」没有抓手。

## 3. 操作时机（何时动）

| 时点 | git 动作 | 类别 | 执行 | 说明 |
|---|---|---|---|---|
| 启动（工件仓库未 git 化） | `init` | 写 | 人 | skill 提醒 |
| 3.4 出口 | `commit` 候选 | 写 | 人 | 本轮唯一强提醒；commit 即冻结 |
| 3.5 验证 | `archive` | 读 | skill | 提取候选 commit 到仓库外干净上下文 |
| 3.6 发布 | `tag` + `commit`（留痕 + changelog） | 写 | 人 | 门禁八条全过后 |
| 生产恶化 | `rollback`（切上一 tag + 追加回滚条目） | 写 | 人 | 带新证据重入归因 |

> commit 在 3.4 出口、tag 在 3.6 门禁后，中间隔着验证——验证对象 = 发布对象（tag 指向 3.4 那次候选 commit，与 05 报告 hash 一致）。

## 4. 命令与命名规范

- **commit message**：`[任务编号] 摘要`，如 `[T-003] 修复华东区重复输出`。任务编号是迭代日志、commit、changelog 的公共索引。
- **tag 命名**：`v{major}.{minor}`——结构性/接口变更升 major（P1），行为与文案变更升 minor（P2）；P3 表述调整不升版本号、不打新 tag，仅在 changelog 当前版本条目下追加调整小节。只有验证过的版本才有 tag。
- **失败候选**：留在历史中作重试证据；介意主线干净可选任务分支，3.6 时合并回主线。
- **回滚点**：上一版本的 tag；切回时新版本 tag 保留在历史，不删除。

## 5. 推荐使用方式

1. **每轮最少 2 个 commit**：3.4 候选（源码）+ 3.6 归档（留痕 + changelog）。其中 3.4 那次是唯一强提醒的写操作。
2. **留痕（01→03 产出）的中途 snapshot 交人自定**：不强求逐状态 commit，可随 3.6 归档一并提交。
3. **机械交给 skill、裁决交给人**：skill 负责读与在正确时点提醒；是否提交、提交哪些（含敏感剥离），由人拍板。
