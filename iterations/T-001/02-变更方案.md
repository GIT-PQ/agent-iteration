## 根因摘要

skill 层沿用了「agent 直接执行 git 写操作」的旧表述，而 P-2 裁决确定：git 写操作不可逆或难逆，必须交人执行、skill 只在守卫点提醒（提醒携带冻结语义）。归因来源：plan.md §1.2——指南 4.6 原本只定义 commit/tag 两个写入时点，git 介入的边界与分工从未定义，skill 层因此默认「agent 代执行」。

## 修改方案

- 改动点 1：SKILL.md 全部 git 写操作点改为「提醒人执行」
  - 位置与思路：七处——①「纯笔误不开任务」段（L13）：直接修改 + commit → 修改后提请人 commit；②「启动流程·确定工件与其仓库」（L17）：`git init` → 提醒用户执行，补一句最小目录检查与 `.gitignore` 建议（`results/*`）；③「3.4 出口守卫」（L104）：commit 候选 → 提醒人提交（附 `[任务编号] 摘要` 格式与冻结语义），**人确认提交后才放行进 3.5**；④「3.6 活动」（L120）：打 tag、留痕/changelog commit → 提醒人执行；归档检查是读操作，仍由 skill 做；⑤「3.6 回滚」（L121）：切回上一 tag → 提醒人执行；⑥「横切规范速查·git 分工行」（L133）：改为写/读分治一行——写交人+提醒（init/commit/tag/rollback），读自动（archive/diff/log）；⑦「目录」区 04-implementation.md 行（L164）：小节名「git 提交规范」→「git 提交提醒」，与改动点 2 的改名联动，不改则目录与正文漂移。
  - 消除根因的逻辑：写操作执行主体从 agent 换成人，skill 保留守卫点触发与规范内容（message 格式、命名），「是否提交、提交哪些」由人拍板。
  - 关联标准：P-2 裁决 2（写/读分治）、3（操作时机）。
- 改动点 2：references/04-implementation.md「git 提交规范」小节
  - 位置与思路：小节改为「git 提交提醒」；执行主体改为人；提交时机与 message 格式保留、作为提醒内容；出口守卫补「人确认提交后放行」。
  - 消除根因的逻辑：3.4 的行为规约与 SKILL.md 出口守卫对齐，消除「agent commit」残留。
  - 关联标准：P-2 裁决 2、3。
- 改动点 3：references/06-release.md 三小节
  - 位置与思路：打 tag / 写 changelog / 回滚的动词改为提醒人执行；「changelog 作为紧随 tag 的独立 commit」句改为「tag 后追加」（与设计层 06 模板同步）；原子化恢复说明保留、主语改人。
  - 消除根因的逻辑：3.6 与回滚的写操作主体统一交人。
  - 关联标准：P-2 裁决 2、3。
- 改动点 4：assets/templates/06-changelog模板.md（运行层副本）
  - 位置与思路：头部「生成时机」句「作为紧随其后的独立 commit」→「后追加」，与 `docs/guide/templates/` 设计层副本同步。
  - 消除根因的逻辑：消除 git 时机细节在模板层的残留（指南层已清）。
  - 关联标准：P-2 裁决 4（落地）。
- 改动点 5：scripts/state_check.py 提示文案四处
  - 位置与思路：①L25 启动提示「git 化」补执行主体——改为提醒人执行（init 为写操作）；②L70「自检通过后 commit」→「自检通过后提醒人 commit，人确认提交后进入 3.5」；③L82「执行回滚」→「提醒人执行回滚」；④L84-85「打 tag … → changelog 条目」→「提醒人打 tag、提醒人提交留痕与 changelog」；「归档检查」仍由 skill 做（读操作）。判定逻辑（文件存在性扫描）不动。
  - 消除根因的逻辑：脚本的「下一步」提示是 skill 面向执行 agent 的引导文案，留旧口径会在守卫点之外形成「agent 自行 commit/tag/回滚」的绕行通道。
  - 关联标准：P-2 裁决 2（写/读分治）、3（操作时机）。裁决 4 的落地清单未点名 scripts，纳入依据是裁决 2 的原则（2026-09-15 维护者裁决：脚本提示须与方案口径一致）。
